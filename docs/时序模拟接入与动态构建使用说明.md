# FactoryNet 时序数据模拟与动态构建

## 这项功能解决什么问题

FactoryNet 文件本身是一组已经记录好的 CNC 过程传感器数据。普通构建会一次性读完文件并写入图谱；“时序模拟”把同一文件当作一个持续到达的数据流：后端按照原始 `time_s`（相对经过秒数）分批读取，每提交一批就更新 FalkorDB 实例图，页面同时显示最新原始记录和已经提交的图谱。

这里变化的是实例，不是本体 Schema。`Machine`、`Episode`、`Observation`、`ProcessPhase` 等类别和关系在开始前固定，随后只新增观测、连接关系和来源证据。因此演示可以清楚地说明“数据逐步到达，实例图逐步长出来”，也不会把尚未观察到的类别误认为动态生成的 Schema。

## 页面操作

1. 进入“数据管理 → 时序数据 → 新建构建”。选择已安装的 FactoryNet CNC，并等待数据分析完成。
2. 在“筛选数据”设置 `episode_id`、`time_s` 范围和最大记录数。空时间范围表示所选过程的完整范围。
3. 在“时间定义”确认 `Ordinal · 顺序值`。FactoryNet 的 `time_s` 不是日期，系统不会把它转换成日期或时区。
4. 在“本体映射”检查字段目标属性和关系。数值传感器列保存为 Observation 属性；`HAS_EPISODE`、`HAS_OBSERVATION`、`OBSERVED_ON`、`NEXT_OBSERVATION` 等关系保证观测不是孤立节点。
5. 在“确认构建”选择“按时间模拟到达”，选择一个或多个 episode，设置批次窗口和速度，然后点击“创建时序模拟”。
6. 模拟页面中的按钮含义：
   - **开始**：从第一个未提交批次开始；
   - **暂停**：在当前批次提交后暂停，不中断已经提交的数据；
   - **继续**：从下一个未提交批次继续；
   - **单步**：只提交一个批次，然后自动暂停，适合老师现场逐步演示；
   - **取消**：停止后续批次，已提交的图谱和证据保留；
   - **速度**：只影响批次之间的演示等待，不改变数据顺序、节点 ID 或关系。
7. 左侧“最近到达的原始记录”是当前批次的实际输入；中间画布是已提交的 FactoryNet 实例图；右侧可点击节点查看属性和 `time_s`；底部列表记录每个批次的时间范围和校验问题。
8. “时间轴”可以拖到任意已提交的 `time_s`，查看该时刻以前的累计图；点击“跟随最新批次”恢复自动跟随。它只是查看快照，不会改变后台播放位置。
9. 画布支持 50/100/200/500/1000、自定义和全部（分页）。全部加载时可以点击“停止加载”，较新的筛选请求会自动使旧请求失效。
10. “继续追加时间段”允许在当前末尾之后加入同一数据源的新区间；提交后点击“继续”即可从 checkpoint 接着播放。刷新或离开页面不会取消任务，回到同一个 replay 地址即可继续查看。

## 数据与稳定性约定

- 数据版本固定为创建 replay 时选定的 DatasetVersion 和文件哈希。
- 默认只选择一个 episode，用户可以多选；多选时按相对 `time_s` 同步推进，不表示不同过程在现实中同时发生。
- 一个时间窗口默认最多 200 行；同一时间窗口超过 200 行时拆成多个批次，但保留相同时间边界。
- “最大记录数”是构建输入上限，默认 5,000；超过上限时按 episode 做时间均匀抽样，并保留每个所选 episode 的代表记录。它不会改变源数据的总行数统计。
- Observation ID 使用 `FactoryNet:Observation:{episode_id}:{source_row_index}`，与批次大小和播放速度无关。
- 每个 episode 的 `NEXT_OBSERVATION` 上一条记录保存在 replay state 中，跨批次连续连接。
- FalkorDB 使用稳定 ID `MERGE`，重复重试不会重复节点或关系；来源证据使用 replay、批次和断言组合哈希，重复重试不会重复 EvidenceRef。
- 只有批次中的时间校验、图写入、SQL 实例和来源证据都完成后，批次才标记为 `completed`。没有有效行或无法生成关系的批次会失败并保留错误信息。

## 接口（供复跑脚本使用）

```text
POST /api/v2/temporal/replays
GET  /api/v2/temporal/replays/{id}
GET  /api/v2/temporal/replays/{id}/batches
POST /api/v2/temporal/replays/{id}/control
POST /api/v2/temporal/replays/{id}/segments
GET  /api/v2/temporal/replays/{id}/graph
```

创建接口只建立 schedule，不会自动启动；控制接口使用 `{"action":"start"}`、`pause`、`resume`、`step` 或 `cancel`。`segments` 只能追加当前结束时间之后的新区间，使用同一数据版本、episode 和本体。

## 五分钟演示顺序

1. 选 FactoryNet，展示源记录数和 episode 列表。
2. 选择一个 episode，在时间定义中指出 `time_s = Ordinal`。
3. 选择“按时间模拟到达”，点击“单步”，让老师看到一批原始记录、节点和关系同时出现。
4. 再单步两次，展示 `NEXT_OBSERVATION` 跨批次连接和节点/关系计数增长。
5. 点击暂停后拖动/查看批次时间轴，再点击继续完成模拟。
6. 点击任意 Observation，展示它的 `episode_id`、`time_s`、传感器属性和来源行号；最后打开本体数据模型查看同一份实例图。
