# ADR 0001：按任务分组的一级导航 + “当前本体”选择器

> 日期：2026-10-22 · 状态：已采纳 · 分支：`feature/nav-reorg`

## 背景

- 提交 `0f13c58` 参照 Foundry 把导航分成两层：全局侧栏只有首页、本体库和几个应用；进入某个本体后，再用本体页里的二级导航（总览 / 资源 / 数据 / 应用 / 治理，约 16 项）找功能。
- 结果是大部分功能藏在第二层，要先进本体页才能看到。
- Workshop 应用（`/apps/workshop`）不在任何导航里，只能手敲地址。

## 决定

1. 左侧一级导航按“用户正在做什么”分组：数据接入 / 本体建模 / 探索 / 推演 / 应用 / 告警 / 智能体，另设“系统管理”。首页、本体库保留在最上面。每一项都指向已有页面，不新增功能（对照表见 `frontend/src/components/navigation.ts`）。
2. 顶栏加“当前本体”选择器，取代“先进本体页、再用二级导航”。本体页里的二级导航和本体切换下拉删除。
3. 当前本体的来源：地址里的本体（`/ontologies/:id`、`?ontology=`、`?ontology_id=`）优先，否则用上次的选择（localStorage，读写失败时忽略）。切换本体时停留在同一个功能。
4. 没选本体时，需要本体的入口打开“先选择本体”页（`/apps/<功能>`），选完直接进入该功能。
5. 旧链接不变：`/ontologies/:id?tab=…`、`/apps/objects`、`/apps/alerts` 等仍打开原页面，路由没有改。

## 理由

- **Foundry 原则不变**（官方文档）：对象浏览器、告警、情景等都是“跑在某个本体上的应用”，所有页面仍然以本体为范围；改的只是入口，从两层压成一层。
- **按任务分组的一级导航**（第三方产品截图：OntoFlow，见 `docs/research/unofficial/ONTOFLOW_TWIN_APP_BUILDER_2026_10_22.md`）：用户按要做的事找功能，不用先记住功能属于哪一层。
- **选择器放顶栏**（本项目推断）：本体是所有页面共享的上下文，放在顶栏随时可见、随时可换，比藏在某个页面里更直观。

## 取代关系

取代提交 `0f13c58` 中**导航部分**的决定（全局侧栏只放平台级入口 + 本体页内二级导航）。该提交的其他决定继续有效：数据从本体内的“数据源”进入、供应商演示改为已保存的情景研究、旧的 `/what-if` 跳转等。

## 影响

- 侧栏条目从 8 项增加到约 22 项，在 800px 高的屏幕上需要滚动；当前所在项会自动滚到可见位置。
- 本体页 `OntologyDetailPage` 只负责渲染选中的功能，不再自带导航；新功能要出现在导航里，需在 `navigation.ts` 里加一项。
- 全局的 `/scenarios`（通用情景目录）不再出现在侧栏，由“推演 → 情景沙箱”（`/ontologies/:id/scenarios`）替代，旧地址仍可打开。
- e2e 用例 `ontology-navigation.spec.ts` 已按新导航更新。
