# OntoFlow：孪生应用搭建器（Dashboard）

> 日期：2026-10-22 · 来源：用户提供的产品截图（编辑态，“型号研发生产经营风险协同 孪生”应用的“经营风险总览”页）· 证据等级：画面可见的内容为第三方产品截图；机制解释为**本项目推断**
> 原件：`unofficial/ontoflow_twin_app_builder_2026_10_22.jpg`（仅本地，不进 git）
> 白皮书（`OntoFlow本体智能开发平台+AbutionGraph本体数据库-技术与应用白皮书.pdf`）只提到“推送结果到可视化大屏”，没有搭建器细节。

## 一句话结论

这是**用组件搭建出来的页面**，不是为这个客户定制开发的。它的上手速度主要靠三点：分区模板、组件库、一键绑定数据（可能还有 AI 生成）。行业定制只体现在个别预制组件上，比如地图。

## 对方怎么做的（画面可见）

- **编辑态的界面框架**：顶部有 草稿 / 已保存 / 发布 / 开发中 / 演示，以及“绑定数据”按钮。左边是页面列表，带 `+新建`，每页有英文标识（home、supplier、shortage、resource、project、fund、batch）。右边是属性面板，标签页有 `数据 / 样式 / 组件库 / 区域 / 接口(13) / AI助手`，提示文字是“选中画布上的组件，或打开组件库添加，也可直接绑定数据一键完成”。
- **分区模板**：画布分成 `SCENE 场景区`、`KPI 指标区`、`INSIGHT 洞察区`，每个区都有自己的 `+组件` 按钮。布局只能在“标准 / 分屏”之间切换。
- **组件**：
  - 地图：中国地图，按风险等级用红圆、黄三角、绿点标出公司，还有连线；
  - 8 张 KPI 卡：样式统一，带单位；
  - 风险告警列表：带“严重”标签和时间，按严重度排序；
  - 环形图：中间显示合计，图例带占比；
  - 横向排行条：物料缺口排行；
  - 资源负荷率条；
  - 表格：列头直接是 `id`。
- **全局控件**：时间范围（24 小时）、刷新方式（手动）、刷新按钮；底部状态栏写着“控制台 正在拉取数据…”。
- **联动**：表格标题写着“重点风险对象（点选联动专题页）”。
- **导航**：一级导航按用户要做的事划分，依次是 探索 / 智能体 / 数据摄取 / 数据资产 / 本体设计 / 本体建模 / 推演沙盘 / 孪生应用 / 图可视化 / 知识库，下面再单独分出“系统管理”。

## 推断的机制（本项目推断）

- **“一键绑定”**：选一个数据源后，平台读取字段和类型，按类型自动生成组件，填进当前模板的各个区。对应关系大致是：数值 → KPI，类别 → 环形图，带坐标 → 地图，列表 → 表格。依据是列头直接显示原始字段名 `id`。
- **`接口(13)`**：页面背后绑定了 13 个数据接口，数据在运行时实时拉取。
- **AI 生成**：页面右侧有 `AI助手`、`智能问数`，7 个页面又按业务主题排得很整齐，推测整个应用由 AI 一次生成，再由人调整。

## 和我们现状的差距（2026-10-22）

| 方面 | OntoFlow | 本项目 Workshop |
|---|---|---|
| 数据源 | 多种接口 | 只有 Study 运行结果（正在补对象集和告警） |
| 组件 | 地图、环形图、排行条、告警列表、KPI 卡 | 指标条、表格、堆叠柱状图、时间格子表、决策类组件 |
| 版面 | 分区模板 | 24 列自由网格 |
| 配置方式 | 一键绑定 / AI 生成 | 每个字段手动配置 |
| 全局控件 | 时间范围、刷新方式 | 无 |
| 导航 | 一级导航按任务划分；搭建器里有页面列表一栏 | 全局导航 + 本体内二级导航，Workshop 不在导航里 |

## 不该照搬 / 存疑

- **原始字段名直接当列头**：这是一键绑定的副作用，我们应该用本体的显示名。
- **中国地图**：边界数据需要有审图号，来源合规才能用。先用 Natural Earth 世界地图。
- **对方的数据接口来源、权限模型看不出来**：截图里没有相关信息。我们的数据源必须在服务端解析，并沿用本体权限。
