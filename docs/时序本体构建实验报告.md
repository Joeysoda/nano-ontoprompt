## 目标

Nano-OntoPrompt 将表格、文档和传感器记录映射为本体实例，并把可追溯的实例图写入按 ontology 隔离的 FalkorDB。C-MAPSS 是原型回归数据，不代表已确定的工厂生产数据源。

## 实现

可视化交互参考 Semantica 的“筛选 → 可视化 → 解释 → 调查”工作流：先用数据源、类型和时间窗口缩小画布，再同步查看结构/实例图，点击节点查看属性与证据，最后用快照、差异和增长曲线调查变化。[Semantica Visualization 指南](https://github.com/semantica-agi/semantica/blob/main/docs/guides/visualization.md)

- `ordinal`：C-MAPSS 的 `cycle` 映射为 `event_seq`，不伪造日期。
- `instant`：ISO 时间解析为 UTC；非法时间记录 issue，不猜测修复。
- `interval`：保存 `valid_from/valid_to`，结束早于开始时报错。
- Observation/Event 节点使用稳定 ID；关系写入使用批量 `MERGE`，重复导入幂等。
- `/data/temporal` 是 Nano 原生的四步入口：选数据 → 配置时间语义 → Brick 映射 → 执行并查看结果。
- `POST /api/v2/ontologies/{id}/temporal/runs` 创建异步 ConstructionRun；Worker 分批读取 BTS 投影并写入 FalkorDB。
- `GET /api/v2/ontologies/{id}/temporal/snapshot|timeline|diff|growth` 支持当前快照、时间轴、双时刻差异和增长曲线。
- `POST /api/v2/ontologies/{id}/graph/temporal/import` 仍保留给 C-MAPSS/Scania 的有界批量回归。
- `GET .../graph/temporal/relations` 支持关系类型、主客体、序列、当前/历史筛选。

## 演示步骤

1. 启动 FalkorDB、PostgreSQL、Redis、Nano 后端和 Worker，登录后进入“数据管理 → 时序数据”。
2. 选择 BTS Site B，确认流数量、记录数、时间范围和 `Site_B.ttl` 来源。
3. 选择 `instant`，实体列为 `stream_id`，时间列为 `event_time`；也可以切换到 `ordinal` 或 `interval` 做规则验证。
4. 点击“创建时序本体构建任务”，等待 ConstructionRun 进入“已完成”。问题行会单独计数，不会猜测日期。
5. 用时间轴拖动/播放并点击“查看当前快照”；“打开 Schema / 实例图”可进入 Graph 页，按类型和时间窗口筛选。
6. 填写两个 ISO 时刻后点击“比较两个时刻”，查看新增/移除节点和边；节点详情中的 `event_time`、`stream_id` 和 `source_row_index` 对应原始 CSV。
7. 重复运行同一个数据源，FalkorDB 的稳定 ID + `MERGE` 保证实例数量不因重试持续增长。

## 验收边界

C-MAPSS 继续作为 ordinal/cycle 快速回归；BTS Site B 是本阶段的 instant 时序演示和 Brick metadata 对照数据。当前 CSV 是交互下采样，不宣称已下载全量 BTS，也不宣称完成大规模性能测试。BTS 官方仓库：[DIEF_BTS](https://github.com/cruiseresearchgroup/DIEF_BTS)。NASA 数据入口：[C-MAPSS](https://data.nasa.gov/dataset/?organization=nasa&res_format=ZIP&tags=ivhm&tags=phm&tags=prognostics)。
