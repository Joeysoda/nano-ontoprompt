# 大规模高并发架构方案

本阶段只交付设计，不发布未经实测的吞吐或延迟结论。

## 目标架构

`ingest`、`media`、`llm`、`audit` 使用独立 Celery 队列和 Worker；MinIO 保存原始内容，PostgreSQL 保存 ConstructionRun/EvidenceRef，Redis 负责任务队列和限流，FalkorDB 保存实例图。采用流式读取、可配置批次、checkpoint、幂等键、失败重试、死信队列、背压和每 ontology 写入锁。

## 后续实验协议

未来使用 LUBM 1万/10万/100万/更大规模档位，覆盖官方 14 个查询，并设置并发 1/5/20/50。记录吞吐、P50/P95/P99、失败率、内存和恢复时间，所有数值待实测。LUBM 支持可重复、可定制数据生成：[官方页面](https://swat.cse.lehigh.edu/projects/lubm/)。本阶段不执行压力测试、云部署或高可用改造。
