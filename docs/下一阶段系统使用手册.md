# 下一阶段系统使用手册

## 启动

在 Nano 仓库按现有 `docker-compose.yml` 启动 PostgreSQL、Redis、FalkorDB、后端和前端；确认 `/health` 与 `/api/v2/.../integrations/status`。首次使用先注册/登录，再在 Models 页面配置本地 Ollama `qwen3.5:0.8b`。

## 主流程

1. 进入“数据管理 → 时序数据”，选择 BTS Site B；确认流数量、记录数、字段和时间范围。
2. 配置 `instant`/`ordinal`/`interval` 时间语义、实体列和时间列，非法数据会进入问题清单。
3. 点击“创建时序本体构建任务”，等待进度从读取、标准化、写入 FalkorDB 到保存证据完成。
4. 在结果页用时间轴播放或跳转时刻，点击“查看当前快照”；“打开 Schema / 实例图”进入 Cytoscape 图视图。
5. 在 Graph 的“数据实例”中按实体类型、cycle 范围和当前/全部历史关系筛选；点击节点或边查看属性和时间证据。
6. 在时序结果页填写两个时刻并运行差异比较；增长曲线显示完整计数，画布只渲染最多 300 个节点。
7. “数据管理 → 常规数据”复用现有 Dataset、Pipeline 和 Curated 页面；“多模态数据”先登记原文件，未配置 MiniMax M3 或没有证据时不会猜测跨模态关系。
8. 创建 ontology 后，Info 查看元数据，Entities 管理类，Logic/Actions 管理规则和动作，Files 管理文件，Audit 运行质量审查，Curated 查看审核数据。
9. Models 页面配置本地 Ollama `qwen3.5:0.8b` 做确定性质量检查；Benchmarks 页面输入 gold JSON 运行 OSKGC/CQ4OE 风格对比；Construction Run 查看状态、指标和 EvidenceRef。

## 常见问题

- FalkorDB 未连接：实例图会明确显示不可用，不会把 SQLite schema 当作 FalkorDB。
- Ollama 未启动或模型未拉取：规则结果可以保留，但不能宣称 `llm_used=true`。
- 数据为空：检查 Dataset version、Curated 数据和映射主键。
- 时间错误：查看 import 返回的 issues；系统不会猜日期。
- 审查超时：降低批次或使用分区摘要；不要静默截断实体。

Neo4j 仍保留为旧 Schema/分析兼容入口；新时序、来源追踪和实例图以 FalkorDB 为准。
