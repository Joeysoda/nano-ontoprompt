# 下一阶段系统使用手册

## 启动

在 Nano 仓库按现有 `docker-compose.yml` 启动 PostgreSQL、Redis、FalkorDB、后端和前端；确认 `/health` 与 `/api/v2/.../integrations/status`。首次使用先注册/登录，再在 Models 页面配置本地 Ollama `qwen3.5:0.8b`。

## 主流程

1. Data → Pipelines 创建连接、Dataset、转换和 Curated 数据。
2. Pipeline Mapping 建立实体类、字段映射和主键，运行 Apply/Build all。
3. 创建 ontology；Info 查看元数据，Graph 切换“本体结构/数据实例”。
4. 数据实例视图可筛实体类型、cycle 起止和当前/全部历史关系；点击节点或边查看属性和时间证据。
5. 需要文档/图片时先上传媒体，再把 MarkItDown/OCR 结果通过 multimodal fragments API 保存；没有证据不建立跨模态边。
6. 评测实验页面填写 ontology ID 和预测/gold JSON，运行 OSKGC/CQ4OE 风格 gold 对比。
7. 使用 Construction Run 查询状态、指标、错误、产物和 EvidenceRef；用 assertion provenance 查看单条断言来源。

## 常见问题

- FalkorDB 未连接：实例图会明确显示不可用，不会把 SQLite schema 当作 FalkorDB。
- Ollama 未启动或模型未拉取：规则结果可以保留，但不能宣称 `llm_used=true`。
- 数据为空：检查 Dataset version、Curated 数据和映射主键。
- 时间错误：查看 import 返回的 issues；系统不会猜日期。
- 审查超时：降低批次或使用分区摘要；不要静默截断实体。

Neo4j 仍保留为旧 Schema/分析兼容入口；新时序、来源追踪和实例图以 FalkorDB 为准。
